# Module 5: SSL/TLS and Certificates

## The Analogy: The Sealed Envelope

**Without encryption (HTTP)**:
- You write your message on a postcard
- Everyone who handles it (postman, postal workers, ISPs) can read it
- Your bank password is visible to anyone

**With encryption (HTTPS)**:
- You seal your message in an envelope, locked with a key
- Postal service cannot read it, only the recipient can
- Your bank password is private

HTTPS = HTTP inside an encrypted TLS tunnel. Only your browser and the server have the key.

## What TLS Does

1. **Encrypts data**: ISPs and WiFi sniffers cannot see your traffic
2. **Authenticates the server**: You know you're talking to the real example.com, not a fake
3. **Ensures integrity**: Attacker cannot modify the response you receive

## Certificates: Proof of Identity

A certificate proves the server is who they claim to be.

```
Certificate for: api.example.com
Valid from: 2024-01-15
Valid until: 2024-04-15 (90 days)
Issued by: Let's Encrypt
Public key: [2048-bit RSA key]
Signature: [Signed by Let's Encrypt]
```

### Public Key Infrastructure (PKI)

```
Root Certificate Authority (Let's Encrypt root)
    ↓
Intermediate (Let's Encrypt intermediate)
    ↓
Your Server Certificate (api.example.com)
```

Your browser trusts Let's Encrypt. Let's Encrypt signs your certificate. Therefore, your certificate is trusted.

Without this chain, your certificate is untrusted (self-signed certs).


## TLS Versions: Old and New

### TLSv1.0, TLSv1.1

❌ **Insecure** — predictable random number generators, weak ciphers
NEVER use these.

### TLSv1.2

✅ **Acceptable** — widely supported, reasonably secure
Configure your server for this and above.

### TLSv1.3

✅ **Modern** — very secure, faster handshake
Prefer this.

Nginx configuration:

```nginx
# Only TLSv1.2 and TLSv1.3
ssl_protocols TLSv1.2 TLSv1.3;

# Reject older versions
# (Nginx will reject any TLSv1.0/1.1 connections)
```

## Ciphers: The Encryption Algorithm

A cipher is an algorithm that encrypts and decrypts data.

```
AES-128-GCM     = 128-bit AES with modern AEAD
AES-256-GCM     = 256-bit AES (even stronger)
ChaCha20        = Modern alternative to AES (good for mobile)
```

### Strong Cipher Suite (Nginx)

```nginx
ssl_ciphers 'ECDHE-ECDSA-AES256-GCM-SHA384:ECDHE-RSA-AES256-GCM-SHA384:ECDHE-ECDSA-CHACHA20-POLY1305:ECDHE-RSA-CHACHA20-POLY1305:ECDHE-ECDSA-AES128-GCM-SHA256:ECDHE-RSA-AES128-GCM-SHA256';

# Prefer server ciphers (server chooses, not client)
# Prevents clients from forcing weak ciphers
ssl_prefer_server_ciphers on;
```

### Bad Ciphers

❌ NULL cipher (no encryption)
❌ EXPORT ciphers (intentionally weak for export, 40-bit)
❌ DEFLATE (vulnerable to CRIME attack)

## Session Caching: Reuse Encrypted Session

After the first handshake, cache the session key so repeated requests don't require a new handshake.

```nginx
ssl_session_cache shared:SSL:10m;
ssl_session_timeout 10m;
```

Benefits:
- Faster HTTPS (no TLS handshake on every connection)
- Reduces CPU load on server

## HSTS: Force HTTPS

HTTP Strict-Transport-Security header tells browsers: "Always use HTTPS for this domain, forever."

```nginx
add_header Strict-Transport-Security "max-age=31536000; includeSubDomains" always;
```

Explanation:
- `max-age=31536000` = 1 year
- `includeSubDomains` = applies to *.example.com too
- `always` = send even on error pages

Effects:
- Browser caches this rule for 1 year
- Every request uses HTTPS automatically (user cannot bypass)
- If someone tries to access http://example.com, browser converts to HTTPS

Prevents SSL stripping attacks where attacker downgrades HTTPS to HTTP.

## Real Configuration: PDF Service

```nginx
server {
  listen 443 ssl http2;
  server_name api.example.com;
  
  # Certificate files generated by certbot
  ssl_certificate /etc/letsencrypt/live/api.example.com/fullchain.pem;
  ssl_certificate_key /etc/letsencrypt/live/api.example.com/privkey.pem;
  
  # Only modern TLS versions
  ssl_protocols TLSv1.2 TLSv1.3;
  
  # Strong ciphers
  ssl_ciphers 'ECDHE-ECDSA-AES256-GCM-SHA384:ECDHE-RSA-AES256-GCM-SHA384:ECDHE-ECDSA-CHACHA20-POLY1305:ECDHE-RSA-CHACHA20-POLY1305:ECDHE-ECDSA-AES128-GCM-SHA256:ECDHE-RSA-AES128-GCM-SHA256';
  ssl_prefer_server_ciphers on;
  
  # Session cache (faster TLS handshakes)
  ssl_session_cache shared:SSL:10m;
  ssl_session_timeout 10m;
  
  # HSTS (force HTTPS)
  add_header Strict-Transport-Security "max-age=31536000; includeSubDomains" always;
  
  # Other security headers
  add_header X-Frame-Options "DENY" always;
  add_header X-Content-Type-Options "nosniff" always;
  add_header X-XSS-Protection "1; mode=block" always;
  add_header Referrer-Policy "strict-origin-when-cross-origin" always;
  
  # Proxy to API
  location / {
    proxy_pass http://api_backend;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-Proto https;
    proxy_set_header X-Real-IP $remote_addr;
  }
}

# HTTP redirect to HTTPS
server {
  listen 80;
  server_name api.example.com;
  return 301 https://$server_name$request_uri;
}
```

## Hands-On Lab

### Lab 5.1: Get a Free Certificate

```bash
# Install certbot
apt-get install certbot python3-certbot-nginx

# Get certificate and install in Nginx
certbot --nginx -d example.com -d api.example.com -d www.example.com

# Follow prompts:
# Email: your-email@example.com (for renewal alerts)
# Terms of service: yes
# Share email: no (optional)

# Check installation
ls /etc/letsencrypt/live/example.com/
# fullchain.pem (your cert + intermediate)
# privkey.pem (your private key - KEEP SECRET)
# cert.pem (your cert only)
# chain.pem (intermediate certs)
```

### Lab 5.2: Inspect Certificate

```bash
# View certificate details
openssl x509 -in /etc/letsencrypt/live/example.com/fullchain.pem -text -noout

# Output shows:
# Issuer: C = US, O = Let's Encrypt, CN = R3
# Subject: CN = example.com
# Validity: Jan 15 00:00:00 2024 GMT to Apr 15 00:00:00 2024 GMT
# Public-Key: (2048 bit)

# Check expiration date
openssl x509 -enddate -noout -in /etc/letsencrypt/live/example.com/fullchain.pem
# notAfter=Apr 15 12:00:00 2024 GMT
```

### Lab 5.3: Test HTTPS Connection

```bash
# Check TLS version and cipher
openssl s_client -connect example.com:443 -tls1_2

# Output shows:
# Protocol: TLSv1.2
# Cipher: ECDHE-RSA-AES256-GCM-SHA384
# Certificate: CN = example.com

# Check certificate chain
openssl s_client -connect example.com:443 -showcerts

# Verify certificate validity
curl -v https://example.com/api/health
# Should show: SSL certificate verify OK
```

### Lab 5.4: Test Auto-Renewal

```bash
# Dry-run renewal (doesn't actually renew)
certbot renew --dry-run

# If successful, certificates will auto-renew 30 days before expiry

# Check renewal status
certbot certificates

# Output shows:
# example.com
# Expiry Date: 2024-04-15
# Auto-renewal: Enabled
```

## Cheat Sheet: SSL/TLS

### Certbot Commands

```bash
certbot --nginx -d example.com              # Get cert, auto-config Nginx
certbot --domain example.com --dry-run      # Test without changes
certbot renew                                # Renew expiring certs
certbot renew --force-renewal               # Force renew
certbot certificates                        # List certs
```

### Nginx SSL Configuration

```nginx
ssl_certificate /etc/letsencrypt/live/domain/fullchain.pem;
ssl_certificate_key /etc/letsencrypt/live/domain/privkey.pem;

ssl_protocols TLSv1.2 TLSv1.3;
ssl_ciphers 'ECDHE-RSA-AES256-GCM-SHA384:...';
ssl_prefer_server_ciphers on;

ssl_session_cache shared:SSL:10m;
ssl_session_timeout 10m;

add_header Strict-Transport-Security "max-age=31536000" always;
```

### OpenSSL Commands

```bash
openssl x509 -in cert.pem -text -noout         # View cert
openssl x509 -in cert.pem -enddate -noout      # Check expiry
openssl s_client -connect host:443             # Test connection
```

## Key Takeaways

- **HTTPS = HTTP + TLS** encryption for privacy
- **Certificates prove identity** via PKI chain
- **Let's Encrypt = free, auto-renewal**
- **TLSv1.2 and TLSv1.3 only** — reject older versions
- **Strong ciphers** with modern algorithms (AES-GCM, ChaCha20)
- **Session caching** for faster repeated connections
- **HSTS header** forces HTTPS, prevents SSL stripping
- **Certbot manages certificates** automatically
